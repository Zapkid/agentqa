# Limitations

Honest list, kept current. If something in the README sounds stronger than this page, this page wins.

## 1. The published numbers come from simulated models
- The build environment had **no LLM API keys**. Every number in `RESULTS.md` was measured with the
  deterministic simulated models (`agentqa/llm/simulated.py`, ADR 0003): a hand-written rule
  library per intent (what a competent model would write after reading the docs) plus **declared**
  error rates (cheap 45%, strong 6%, scaled by task difficulty) for missed intents, invented paths and
  fields, undocumented statuses, wrong logic, triage misclassification and uncited evidence.
- These numbers therefore measure the pipeline's **mechanics**: whether Tier 0, the cascade, the
  verifiers, the guards, triage clustering and the eval harness behave as designed, and what each
  mechanism saves relative to the others *under the declared error model*. They say nothing about
  how Gemini, Claude or an OpenRouter model would score. The strategy comparison in particular
  reflects the simulator's assumptions (for example, that a cheap model errs 7x more often than a
  strong one).
- `make eval-live` produces the real-model tables. Until it has been run, the brief's success
  criterion "results table for at least three model configurations" is **not met** with real models.
- The Anthropic, Gemini and OpenRouter adapters are implemented against the installed SDKs
  (anthropic 1.11, google-genai 2.28, openai 3.26) and tested with stub clients only; they have not
  made a live call from this environment. Server-side refusal fallback (Anthropic beta) is enabled
  for Opus/Sonnet 5.5 and untested live.
- Simulated provider-side prompt caching is modelled as "second identical prefix is cached"; real
  provider caching has minimum prefix sizes and TTLs.

## 2. Environment of the build
- **No Docker.** `deploy/docker-compose.yml`, the Collector, Prometheus, Grafana provisioning
  (dashboards generated by `deploy/grafana/build_dashboards.py`) and alert rules are statically
  validated (YAML/JSON parse) only. Container image tags were chosen from memory and are not
  verified against the registries. No Grafana or Phoenix screenshots exist yet.
- The pipeline never needs Docker: target builds run as local uvicorn subprocesses, and every run
  saves its spans to `spans.jsonl`, which the run page and the tests read.
- **No third-party API has been tested.** The build host's network policy denies every outside
  host (checked: petstore3.swagger.io, httpbin.org, restful-booker, dummyjson, fakestoreapi,
  realworld). The Swagger 2.0 and API-key support is exercised only by the local Tasks API
  (`examples/tasks_api/`) and a hand-built document. Expect gaps on real-world specs.
- **Gemini docs were unreachable** from the build host; Gemini model IDs and prices come from
  third-party summaries and the SDK, flagged `verify_before_use` in `config/pricing.yaml`. OpenRouter
  `:free` model IDs and their "list-equivalent" prices are assumptions; free-tier model lists rotate.
- No demo GIF/video and no screenshot of an MCP desktop client were produced (no GUI here). The MCP
  server is verified with the official MCP client over stdio (`tests/test_mcp_server.py`).

## 3. Method caveats
- **Reference-build verification.** The cascade runs each generated test against a known-good build
  when one is configured; in the benchmark that is the clean build, which is also the ground-truth
  baseline. Test validity on clean is therefore near 100% by construction (ADR 0007).
- **Adversarial injection set and judge calibration set** were written by the same author as the
  heuristics and the simulated judge. Their 100% scores show the harness works, not that the defences
  generalise. An independent red-team set is the obvious next step.
- **Strategy comparison at n=3** per configuration: several ablation deltas are within seed-to-seed
  noise; the table shows min–max ranges so this is visible. Each run is cold (fresh store, no lessons,
  no learned stats, LLM cache off), so learned routing and incremental reuse cannot show their value
  inside the strategy table; the memory/incremental runs measure them separately.
- **Hashing embedder.** Measurements used the deterministic hashing embedder plus BM25 (ADR 0004)
  because embedding weights could not be downloaded. Retrieval parameters (k=5, round-robin merge)
  were tuned on the bundled docs, which is a form of fitting to the benchmark.
- **Performance numbers** come from one shared 4-core build host with the target pinned to one core
  (not a container limit). Only relative A/B results are reported; absolute latencies are illustrative.
  The soak test type exists but the benchmark detects the memory leak from a short stepped run, not a
  10-minute soak. SLO-verdict accuracy is reported per run but there is no labelled SLO ground truth.
- **Triage accuracy** is scored per failing test against differential labels; a finding marked
  `needs_review` counts as wrong. Bugs visible only in combination are labelled `interaction` and
  scored as product bugs.

## 4. Not implemented (or only partly)
- Veroniqa (ADR 0010): single-user and local (no authentication); chat history lives in the
  browser session; with the simulated profile, answers are extracts from the documents rather than
  a model's prose, and routing is keyword-based. It has not been run against a real model here.
- Input formats and auth (ADR 0009): Swagger 2.0 is converted, not parsed natively; auth is a
  configured bearer token or API key only (no basic auth, no OAuth token flows); external `$ref`s
  and XML bodies are unsupported.
- The simulated planner/generator are written for the bundled Orders API; against any other API
  with `AGENTQA_PROFILE=simulated` only the Tier 0 (spec-derived) tests are produced.
- F14 stretch goals: Playwright UI generation, LangGraph adapter, Slack alerts.
- Access control, multi-tenancy, tamper-evident audit storage (non-goals; see `docs/ENTERPRISE.md`).
- Gemini explicit context caching (`caches.create`); the adapter relies on implicit caching and
  records `cached_content_token_count`.
- Resume restores task artifacts from checkpoints, but in-memory run counters (hallucination stats,
  delegation summary) cover only the work done after the resume.
- Self-consistency voting on escalated tasks (F12.7) is not implemented; escalated tasks get one T2
  attempt plus one repair.
- Learned routing uses Thompson sampling per (category, tier) only; it does not use the difficulty
  features as context.
- Webhook signature generation for perf scenarios targets a non-existent order (404 after the
  handler's work) rather than a real payment flow.
