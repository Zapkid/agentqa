# 5-minute demo script

Audience: a buyer (and the engineer they bring). Setup before the call: `uv sync`, optionally keys in
`.env` and `AGENTQA_PROFILE=mixed`; with Docker, `make up` (Phoenix on :6006, Grafana on :3000).
Without keys the demo runs on the simulated models: say so on the first slide and keep saying so.

| # | beat | do | what to say |
|---|---|---|---|
| 1 | The problem | (title slide) | "Your API ships weekly; your test suite lags months behind the requirements, and the bugs that hurt — wrong totals, one customer seeing another's data, a cancelled order leaving the warehouse — are business rules, not schema errors." |

## Questions a skeptical customer asks

**"Where does our data go?"** Specs and docs are processed locally; embeddings are local. Only LLM
calls leave, to the providers you configure, and they can be private endpoints. Logs, traces and
reports are redacted centrally. See `docs/ENTERPRISE.md` for what is and is not covered.

**"LLMs hallucinate. Why trust a generated test?"** Every test is checked before it runs: the
paths, methods, fields and status codes it uses must exist in your spec (the grounding guard),
the code passes static and security checks, and where a known-good build exists the test must pass
on it. We publish the hallucination rate: the share of generated tests the guard rejected before repair.

**"Why would I trust a finding?"** A finding without cited evidence is downgraded to `needs_review`;
ambiguous findings go to a judge from a different model family. Ground truth for our numbers comes
from differential testing, not from the model grading itself.

**"What does it cost?"** Every call is priced (actual and list-equivalent) and capped by a run
budget; the run stops cleanly with a partial report if it would exceed it. Per-run cost is in the
report header and on the Grafana dashboard.

**"Are we locked in to one vendor?"** One client interface, three providers today, per-role routing
and automatic fallback; switching is a config change. Prompts are versioned files.

**"Can I trust a cheaper model?"** Only behind verification. The cheap model gets the easy tasks; when
its output fails a check it is repaired once and then escalated to the strong model. The ablation
shows what happens without that gate: recall and triage accuracy drop. Measure it on your API with
`make eval-live` before deciding.

**"Is this production-ready?"** No: it is a proof of concept. `docs/LIMITATIONS.md` lists what is not
done, starting with the fact that the published numbers come from simulated models.
